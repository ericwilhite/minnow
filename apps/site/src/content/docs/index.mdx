# Minnow

<p class="lede">
  Minnow is a relational database that runs entirely in the browser: typed queries, real SQL, live
  results, and durable storage built on immutable compressed columnar blocks over IndexedDB.
</p>

There is no server, no WASM blob, and no build step. You declare a schema once, and that one
declaration drives migrations, autocomplete, row types, typed writes with `returning`, and live
subscriptions. Underneath sits an engine with MVCC snapshots, atomic multi-tab publication,
vectorized execution with explicit memory budgets, and background compaction.

```ts
import {
  createMinnow,
  MinnowDatabase,
  column,
  schema,
  table,
  type InferDatabase,
} from "@minnowdb/core";
import { IndexedDbBlockStore } from "@minnowdb/core/storage";

const people = table("people", {
  name: column.string().unique(),
  score: column.number(),
  joined: column.datetime().nullable(),
});
const appSchema = schema([people]);
interface DB extends InferDatabase<typeof appSchema> {}

const database = new MinnowDatabase(await IndexedDbBlockStore.open({ name: "app-db" }));
await database.migrate(appSchema);

const db = createMinnow<DB>(database, { schema: appSchema });
const rows = await db
  .selectFrom("people")
  .where("score", ">=", 10)
  .select(["name", "joined"])
  .orderBy("name")
  .execute(); // Array<{ name: string; joined: Date | null }>
```

> Minnow is experimental. The version-zero block format carries no compatibility promise, and the
> SQL surface is a correctness-first subset, not full SQL-92 coverage.

## Design commitments

A few properties are constraints on the project, not aspirations — the full list is in
[Architecture](/docs/architecture/):

- **IndexedDB is authoritative.** Correctness never depends on BroadcastChannel, Web Locks,
  page-close handlers, or successful background work. The durability contract ends at a
  successfully committed IndexedDB transaction.
- **Published data is immutable.** Writes append compressed columnar segments and publish them with
  an atomic manifest compare-and-swap; another tab sees the old version or the new one, never a
  partial write.
- **One plan, two front ends.** Builder queries compile to the exact plans their SQL equivalents
  produce, enforced by structural plan-equality tests.
- **The engine is owned.** Parser, binder, planner, optimizer, and executor are implemented here —
  no SQLite, no DuckDB, no WASM engine underneath.
