---
title: The typed client
description: A schema-aware query builder with inferred row types, shipped as its own package.
---

```bash
npm install @minnowdb/client
```

`@minnowdb/client` is optional. SQL remains the engine's full language; this package gives it a
typed builder and a parameter-safe SQL entry point. Use whichever reads more naturally for the
job, and mix them in one application.

It ships separately so it can move at its own pace without requiring an engine release. Builders
produce parameterized SQL, then the SQL engine checks and runs it. That means SQL and the typed
client share the same rules, cache, and execution path.

## What you get

One schema declaration drives migrations, row types, and every query:

```ts
import { MinnowDatabase, column, schema, table } from "@minnowdb/core";
import { IndexedDbBlockStore } from "@minnowdb/core/storage";
import { createMinnow, type InferDatabase } from "@minnowdb/client";

const appSchema = schema([
  table("customers", {
    customer_id: column.number().unique(),
    name: column.string(),
    city: column.string().nullable(),
  }),
]);

interface DB extends InferDatabase<typeof appSchema> {}

const database = new MinnowDatabase(await IndexedDbBlockStore.open({ name: "shop" }));
await database.migrate(appSchema);
const db = createMinnow<DB>(database, { schema: appSchema });

const rows = await db
  .selectFrom("customers")
  .select(["name", "city"])
  .where("city", "=", "London")
  .execute();
// Array<{ name: string; city: string | null }>
```

The client also runs the full SQL suite directly:

```ts
import { sql } from "@minnowdb/client";

const rows = await db.query<{ name: string }>(
  sql`SELECT name FROM customers WHERE city = ${"London"}`,
);
const result = await db.execute(sql`UPDATE customers SET city = ${"Paris"} WHERE name = ${"Ada"}`);
```

Interpolated values stay parameters, so the engine can reuse one compiled plan when the values
change. `sql.identifier("table", "column")` safely quotes a dynamic identifier; ordinary values
should always use regular interpolation.

Builders use that same path. Call `toSQL()` when you want to inspect or log the statement a builder
will run.

The named `interface DB extends InferDatabase<...> {}` is the standard form: it keeps hovers,
errors, and emitted declarations printing `Minnow<DB>` instead of the fully expanded schema, which
matters as soon as you have more than a table or two.

## Try it without installing anything

The [console on the home page](/#console) has a TypeScript tab: an editor running the real
TypeScript language service, loaded with the declarations these packages publish, over a database
of about 590,000 rows already built in your browser. Autocomplete lists the tables that exist, a
misspelled column is marked before anything runs, and pressing Run executes the snippet against
that database. It is the same `db` these pages describe.

## It wraps either half of the worker pair

`createMinnow` takes a `MinnowDatabase` or a `MinnowDatabaseClient`, so moving the engine into a
worker changes where you get the driver from and nothing about the queries you write. See
[Workers & multi-tab](/docs/engine/workers).
