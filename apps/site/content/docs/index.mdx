title: A browser native SQL database
description: Run PostgreSQL-style SQL over durable browser-local data.
---

Minnow is a columnar SQL database for the browser. It stores data in IndexedDB or OPFS and runs
queries on the device, so an application can filter, join, aggregate, and update local data
without a server round trip.

```ts
import { MinnowDatabase } from "@minnowdb/core";
import { IndexedDbBlockStore } from "@minnowdb/core/storage/indexeddb";

const db = new MinnowDatabase(await IndexedDbBlockStore.open({ name: "shop" }));

await db.execute(`CREATE TABLE orders (
  order_id INTEGER PRIMARY KEY,
  customer_id INTEGER NOT NULL,
  total NUMERIC(12, 2) NOT NULL,
  placed_at TIMESTAMP NOT NULL
)`);

const { rows } = await db.query(`
  SELECT DATE_TRUNC('month', placed_at) AS month, SUM(total) AS revenue
  FROM orders
  GROUP BY DATE_TRUNC('month', placed_at)
  ORDER BY month DESC
`);
```

<Callout type="warn" title="Experimental">
  Minnow is in 0.x, so minor releases can include API and SQL breaking changes. The separately
  versioned block-format 2, snapshot-format 1, and native OPFS-layout 5 bytes are locked; an
  incompatible future writer must use a new format number. Pin exact package versions. The
  [versioning guide](/docs/reference/versioning) explains the policy.
</Callout>

## Why use Minnow

- **PostgreSQL-style SQL.** Use familiar parameters, joins, CTEs, window functions, grouping sets,
  upserts, `RETURNING`, triggers, exact decimals, JSON/JSONB, arrays, enums, sequences, and
  savepoints. The [feature matrix](/docs/sql/feature-matrix) names the exact supported forms and
  every deliberate difference.
- **Fast scans over local application data.** Minnow stores compressed columns, reads only the
  columns a query uses, and skips blocks that cannot match. Secondary indexes speed up selective
  filters and ordered reads.
- **Durable and safe across tabs.** Writes publish atomically to IndexedDB or OPFS. Each query sees
  one stable version, even while another tab commits.
- **No server or Wasm setup.** Minnow is plain JavaScript. There is no database process, Wasm
  module, compile delay, `SharedArrayBuffer`, or special response header to configure.
- **Works off the UI thread.** The worker client exposes the same query, write, migration,
  snapshot, and maintenance calls as the direct engine.
- **Handles larger working sets.** Queries run in batches. Sorts and grouped results can spill to
  storage when they exceed the configured execution budget; pull-driven cursors transfer one
  bounded page at a time.
- **Reactive, typed views.** Kysely live queries preserve inferred rows and result plugins, with
  keyed changes, ordered windows, and a React external-store hook.

## Choose how you query

Both interfaces use the same SQL engine and can share one database.

| Interface                                   | Use it when                                               |
| ------------------------------------------- | --------------------------------------------------------- |
| [`MinnowDatabase`](/docs/sql)               | You want direct SQL and the smallest dependency set.      |
| [`@minnowdb/kysely`](/docs/adapters/kysely) | You want Kysely's type-safe PostgreSQL query-builder API. |

## Where Minnow fits

Minnow works well for offline tools, local dashboards, data explorers, and applications that keep
their own relational data on the device. It supports both day-to-day keyed reads and writes and
analytical queries over the data that accumulates.

Minnow is not a server database or a sync service. It works on one device, inside one browser's
storage quota. If you need replication, multi-user access, exact SQLite file compatibility, or
the full PostgreSQL server, see the [comparison guide](/docs/comparison).
