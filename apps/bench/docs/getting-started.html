Getting started

MinnowDatabase is an experimental browser-only relational database built around immutable compressed columnar blocks and IndexedDB. It includes persistent writes and snapshots, a deliberately limited read-only SQL API with a columnar executor, resumable compaction, lease-aware garbage collection, and deterministic fault injection.

Experimental. The version-zero block format carries no compatibility promise, and the SQL surface is a correctness-first subset, not full SQL-92 coverage.

Logical types

The public type system is intentionally small. A table column is one of:

  • boolean
  • number
  • string
  • datetime

Numeric widths and physical encodings are storage details, not schema choices exposed to callers. Row IDs are assigned internally; callers do not choose an integer size.

First session

Declare a schema, open a block store, migrate, and work through the typed facade — one declaration drives migrations, autocomplete, row types, typed writes with returning, and live queries: 

import {
  MinnowDatabase,
  Minnow,
  column,
  schema,
  table,
  type InferDatabase,
} from "@minnowdb/core";
import { IndexedDbBlockStore } from "@minnowdb/core/storage";

const people = table("people", {
  name: column.string().unique(),
  score: column.number(),
  joined: column.datetime().nullable(),
});
const appSchema = schema([people]);

const store = await IndexedDbBlockStore.open({ name: "app-db" });
const database = new MinnowDatabase(store);
await database.migrate(appSchema);

const db = new Minnow<InferDatabase<typeof appSchema>>(database, { schema: appSchema });

const written = await db
  .insertInto("people")
  .values([
    { name: "Ada", score: 10, joined: new Date() },
    { name: "Grace", score: 20 }, // joined pads to null
  ])
  .returningAll()
  .execute();

const rows = await db
  .selectFrom("people")
  .where("score", ">=", 10)
  .select(["name", "joined"])
  .orderBy("name")
  .execute(); // Array<{ name: string; joined: Date | null }>

Every write validates before it stores anything and publishes immutable columnar blocks through an atomic manifest compare-and-swap, so a reader in another tab sees either the old version or the new one, never a partial write. Builder queries compile to the exact plans their SQL equivalents produce — see the query builder.

The SQL and batch layer

Underneath the facade sit raw SQL and column-based batches — the layer the builders compile onto. Reach for it for bulk ingestion, ad-hoc SQL, or when compile-time types are not needed: 

await database.insertBatch("people", {
  columns: {
    name: ["Katherine", "Linus"],
    score: [30, 25],
    joined: [new Date(), null],
  },
});

const resultSet = await database.query(`
  SELECT score, COUNT(*) AS people
  FROM people
  WHERE score >= 20
  GROUP BY score
  ORDER BY score DESC
`);

Tables can also be created without the schema DSL via createTable — see the write API.

Run it in a worker

MinnowDatabase runs wherever you construct it — the examples on the overview page run it on the main thread against an in-memory store, and the calling code is identical either way because the public API is asynchronous throughout.

For real datasets, run it in a dedicated worker: IndexedDB access, block decoding, and query execution are heavy enough to jank the main thread. The library ships both sides of that channel — @minnowdb/core/worker is a ready-made worker entry, and MinnowDatabaseClient (from @minnowdb/core/client) is a main-thread async proxy of the full API. Your application contributes one line — constructing the Worker: 

import { MinnowDatabaseClient } from "@minnowdb/core/client";

const client = new MinnowDatabaseClient(
  new Worker(new URL("@minnowdb/core/worker", import.meta.url), { type: "module" }),
  { store: { kind: "indexeddb", name: "app-db" } },
);
// Same code as above — the facade wraps the client exactly like a database:
await client.migrate(appSchema);
const db = new Minnow<InferDatabase<typeof appSchema>>(client, { schema: appSchema });

See Run it in a worker for the full client API, bundler setups, and custom worker entries built on exposeDatabase().

Correctness never depends on BroadcastChannel, Web Locks, page-close handlers, or successful background work. IndexedDB is authoritative; the durability contract ends at a successfully committed IndexedDB transaction.

Testing with an in-memory store

For unit tests, substitute a MemoryBlockStore for the IndexedDB store. It implements the same storage interface, so table creation, batch writes, queries, compaction, and garbage collection behave identically without touching real browser storage.
